# 跨领域对照表

下面这些领域都长期解决过同一类问题，做法已经很成熟。遇到相似的需求时，先查这张表。

## 信息筛选与推送（资讯、监测、告警类需求）

| 领域 | 成熟做法 | 可搬的原则 |
|---|---|---|
| 情报分析 | 优先情报需求（PIR）→ 征候与预警指标（I&W）→ 采集计划 | 从“要做的决定”倒推“要盯的指标”，再倒推“去哪里找”。不要从“有哪些新闻”出发 |
| 运维告警（SRE） | 分级：立即呼叫、开工单、只记录；把告警疲劳当头号敌人 | 推送分档，只有需要马上行动的才打断人；每条推送都要能对应到一个动作 |
| 企业舆情监测 | 按客户定制实体与关键词，日报与突发快报分开 | 维护实体别名表；快报和日报走两条线 |
| 药物警戒 | 信号检测：单份报告不算什么，同一信号反复出现才算 | 弱信号累积到一定程度时升级提醒 |
| 新闻编辑部 | 新闻价值 = 影响面 × 接近性 × 时效 × 冲突性 | “接近性”（和读者有多近）往往是本地化最缺的那一维 |
| 推荐系统 | 显式反馈闭环（有用 / 没用）、冷启动规则 | 一开始靠规则，有了反馈就按反馈每周校准 |

## 规则与流程改造（本地化、迁移类需求）

| 领域 | 成熟做法 | 可搬的原则 |
|---|---|---|
| 软件本地化（i18n / L10n） | 先把可变部分和不变部分分开，再替换可变部分 | 先分出“骨架和纪律”与“参数和定义”，只改后者 |
| 法律移植 | 照搬条文常常失败，得按当地制度重新解释 | 照搬的是原则，不是数字 |
| 精益生产 | 先找瓶颈（约束理论 TOC），只优化瓶颈 | 先确定瓶颈在哪一环，再决定改哪里 |
| 临床试验 | 先定终点指标，再设计干预 | 先写验收指标，再动手改 |
