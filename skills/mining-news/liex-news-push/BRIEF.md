# 任务书：LIEX 经营环境监测技能（第二版）

本文件是改写后的任务要求，用来指导下一轮改造 `liex-news-push`。目标是更深，不是更大：不增加推送量，不增加栏目，只提高“不漏、不错、可验证”的程度。

## 一、要支持的决定

读者是 LIEX 管理层和相关部门的中方同事。技能要让他们在外部规则或经营条件发生变化后，尽快、准确地知道三件事：

1. 什么变了；
2. 现在处于什么法律状态；
3. 同行在同一制度下得到了什么结果。

据此，他们安排合规、申报、对外沟通和经营调整。推送是手段，衡量标准是：

- 重要变化有没有漏；
- 推出去的事实有没有错；
- 推送比官方公布晚了多久。

## 二、先建暴露清单，再定监测范围

不从“有哪些新闻”出发，从“LIEX 暴露在哪些规则和条件之下”出发。

### 1. 建一份暴露清单

逐项列出 LIEX 依赖的东西：

- 矿权和许可，包括环境影响声明（DIA）及其更新周期、用水许可；
- 适用的税收和投资制度，包括矿业投资法规定的财税稳定、RIGI 的适用情况；
- 出口和外汇安排；
- 劳动集体协议和工会；
- 能源供应；
- 物流路线和口岸；
- 关键供应商；
- 周边社区和原住民社区。

### 2. 每项回答四个问题

| 问题 | 例子 |
|---|---|
| 受哪条规则管？ | 某项许可依据哪部法律、哪项决议 |
| 谁有权改？ | 国会、省议会、某个部、法院 |
| 改动会在哪里最先公开？ | 国家公报、省公报、国会法案库、法院公告、市政府社交账号 |
| 变到什么程度算要推？ | 进入哪个阶段、超过多大幅度 |

这四个答案就是监测范围、检索入口和推送标准，替代凭印象写的主题清单。

### 3. 暴露清单不进公开仓库

它涉及 LIEX 内部信息，只作为私有文件上传给智能体，或放在飞书知识库。公开仓库只放一份空白模板。

**事前补漏：** 用“假设三个月后 LIEX 因外部变化吃了亏，最可能是因为什么”倒推，把找到的原因补进暴露清单。

## 三、从一手素材入手

| 素材 | 用途 |
|---|---|
| 阿根廷国家官方公报第一部分（逐日） | 法律、法令、决议的原文和生效日期 |
| 卡塔马卡省官方公报 | 省级法律、法令、权益金和许可类决定 |
| Infoleg、SAIJ 两个官方法规库 | 查一部法规被哪些后续规定修改过，确认现行文本 |
| 国会两院的法案库、委员会议程和表决记录 | 在法案成为法律之前就看到它 |
| 卡塔马卡省议会的会议议程 | 同上，省级 |
| RIGI 评审委员会刊登的批准、驳回决议 | 同行先例的唯一权威来源 |
| ARCA 的总决议，BCRA 的 A 类通讯 | 税收、外汇、利润汇出规则 |
| 国家和卡塔马卡省法院的裁定，特别是环境诉讼（amparo ambiental） | 司法暂停、违宪宣告、针对锂项目用水的先例 |
| 市政府、工会、社区组织的官方公告和社交账号 | 封路、罢工、抗议往往最先出现在这里 |
| 紫金矿业的交易所公告 | 母公司对 3Q 的正式披露 |
| LIEX 过去 12 个月实际应对过的外部事件 | 内部材料，只用于第七节的回测，不进仓库 |

媒体报道是线索，不是依据。任何一条推送里的编号、日期、阶段，都要能在上面某个一手素材里找到原文。

## 四、方法和工具

1. **先查变化，再做搜索。** 每次巡检先逐一检查第三节的官方渠道有没有新文件，比如公报的当日目录、法案库的新增和状态变化；然后才用检索词搜媒体。搜索引擎收录有延迟，不能作为主要入口。
2. **向上游盯。** 法规按阶段跟踪：提交、委员会意见、一院通过、立法通过、颁布、公布、生效、实施细则、司法暂停。要推的是阶段变化，不只是最终结果。
3. **用编号认同一事件。** 优先用法案编号（expediente）、法规编号、决议编号、案号来判断两条报道是不是同一件事；没有编号时，才看主体、动作、对象。
4. **给来源和信息分别评级。** 采用北约情报评级法（Admiralty Code）：
   - 来源可靠性分 A–F；
   - 信息可信度分 1–6。

   官方原文记为 A1；无法取得原文、靠两个独立来源交叉核验的，最高记为 B2。评级写在卡片的来源一行。
5. **不确定性用固定措辞。** 参照美国情报界分析标准（ICD 203）的做法，涉及尚未确定的事项时，只用“已确定”“很可能”“尚不确定”三档表述，不用“或将”“恐将”这类含糊措辞。
6. **推不推由规则决定，分数只表示重要程度。** 推送条件全部是能核对的事实：
   - 有暴露清单里的传导路径；
   - 通过核验；
   - 是新事件，或者阶段发生了变化；
   - 不在排除清单里。

   分数只用来排序和显示分档，不单独决定推不推。
7. **用带锚点的评分表打分。** 每个分档配 3–5 个真实历史事件作锚点，打分时先找最接近的锚点再定分。门槛不凭经验定，用第七节的回测结果确定。
8. **重大事项复核。** 分档为“重大”的，推送前再独立核对一遍编号、日期、阶段和链接。条件允许的，同时提醒法务或政府关系负责人确认。

## 五、地域、范围和排除

- **地域：** 阿根廷国家层面、卡塔马卡省（优先）、Fiambalá 和 Tinogasta 等地方（只收特别重大或直接影响经营、物流、人员通行、供应商、社区关系的事）。不要求每层都有内容。
- **先例：** 其他省份和其他企业的事件，只在构成先例时收，比如 RIGI 的批准结果、针对锂项目的司法裁定、大额并购。
- **排除：**
  - 与矿业和企业经营无实质关联的一般政治和社会新闻；
  - 地方日常事件和普通项目进度；
  - 宣传和营销；
  - 与 LIEX 无关、也没有明确传导效应的细分税务和行政规则；
  - 重复报道；
  - 无法核实的消息。

## 六、核验和写作

### 1. 核验

每条推送必须做到：

- 事件真实，日期准确；
- 主体、名称、编号、机关准确；
- 法律效力、生效日期、适用范围和条件准确；
- 阶段准确；
- 预测和评论不写成事实；
- 链接是本次实际打开过的原文，且和正文对应。

另外，卡片里出现的每个编号、日期、金额，都要能在所引原文里逐字找到。

严禁虚构新闻、法规、编号、日期、来源或链接。

### 2. 写作

- 用正式、简洁、客观的内部通报语言；
- 中文正文，法规和机构名第一次出现时括注西语；
- 结论前置，写清发生了什么、变了什么、处于什么阶段、何时生效、关键的适用条件；
- 不设“对 LIEX 的影响”栏目，不写假设性风险和套话。

### 3. 卡片

- 显示分档和分数、层级和类别、状态、来源及其评级；
- 进展卡片用一句话交代前情；
- 推错了推更正卡片，不删原卡片。

## 七、怎样证明结果是对的（不靠你我判断）

| 证据 | 做法 | 通过标准 |
|---|---|---|
| 历史回测 | 由 LIEX 法务或政府关系人员列出过去 12 个月实际应对过的外部事件，作为标准答案；让技能在当时的时间点上重跑 | 召回率不低于 90%；漏掉的每一条都要写明原因：信源没覆盖、范围判断错，还是门槛太高 |
| 盲评一致性 | 抽 50 条候选事项，由两位 LIEX 同事独立判断推不推、属于哪一档，再和技能的结果比较 | 推不推的一致性（Cohen's kappa）不低于 0.6；不一致的事项用来补充锚点 |
| 外部对照 | 把阿根廷大型律所发布的客户简报、行业专业媒体的重要报道，作为独立名单，看技能有没有覆盖 | 律所简报涉及矿业的事项全部覆盖 |
| 引用自动核对 | 逐条检查卡片里的编号、日期、金额，是否逐字出现在所引原文里；链接是否能打开 | 100% 通过；有一条不过就推更正卡片 |
| 时效 | 记录官方公布时间和推送时间 | 中位数不超过 3 小时 |
| 读者反馈 | 群成员对卡片标记“有用”或“不该推” | 每月回看，“不该推”的占比低于 20% |

**节奏：** 上线前完成回测和盲评；上线后前两周每周回看一次，之后每月一次。

**调整顺序：**

- 漏推，先补暴露清单和信源；
- 误推，先改排除清单和锚点；
- 最后才动门槛。

## 八、交付和约束

- **技能包：** `SKILL.md`、`references/`、`PROMPT.md`，打成可以直接上传给飞书智能体的 zip 包。
- **暴露清单模板：** 进仓库；填好的清单不进仓库。
- **公开仓库：** 不提交飞书 App ID、App Secret、群 ID、Webhook 地址、个人信息和 LIEX 内部资料。
- **AI矿策 的规则：** 只作参考，不要求保持一致，不连接、不修改 AI矿策 的仓库。
