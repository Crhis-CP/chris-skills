# LIEX 新闻监测员（liex-news-push）

飞书智能体（工作伙伴）用的技能。它全天巡检阿根廷国家层面、卡塔马卡省以及 Fiambalá、Tinogasta 的法规政策和经营环境变化，每天在群里出三期中文简报：**晨报、午间报、日报**。每期分正文和简讯两栏：正文是 6 分及以上的事项，写完整，附原文链接；简讯是 4–5 分的事项，每条一句话。期与期之间不重复。

本文件给人看。智能体按 `SKILL.md` 和 `references/` 工作。

## 一、怎么用

1. **下载技能包**：[liex-news-push.zip](https://github.com/Crhis-CP/chris-skills/releases/latest/download/liex-news-push.zip)。这个链接永远指向最新版本，可以直接转发给同事。
2. **新建工作伙伴**：在“想要工作伙伴帮你的团队做什么？”一栏，粘贴第二节的介绍。
3. **上传技能包**，再把智能体拉进推送群。
4. **设置三个定时任务**，内容见第二点五节：
   - 晨报：阿根廷时间 08:00（北京时间 19:00）
   - 午间报：阿根廷时间 13:00（北京时间次日 00:00）
   - 日报：阿根廷时间 19:00（北京时间次日 06:00）
5. **第一次使用**：先发“自检”，再发“演练”，最好在测试群或和智能体的私聊里发。演练会把这一期报编好发在对话里，不算正式的一期，以后的报照常收录这些事项。

App ID、App Secret、群 ID、Webhook 地址只填在飞书后台，不要写进介绍或技能包。

**运行记录表：** 第一次正式出报时，智能体会在设置它的人的飞书云空间“我的空间”根目录下，建一个名为“LIEX 新闻监测员”的文件夹，里面只有一个多维表格“LIEX 新闻监测员 运行记录”，分两张表：“每期记录”（每期查了哪些来源、收了几条、有没有发出）和“收录事项”（收过的每一条，带分数和链接，用来去重）。每个使用者各有一份，智能体不会在这个文件夹以外创建文件。想核对某一期查了什么、为什么没收，看这张表。自检时，智能体会试写一行再删掉；回答“不能”的，说明它没有建表的权限，这时它退回用群消息和记忆功能去重，照常发报。

**技能和指令怎么分工：** 筛选规则和“报”的格式都在技能里，定时任务的指令只说“出哪一期”。以后更新技能，只要替换技能包，指令不用改，两边也不会打架。

## 二、创建介绍（复制到“想要工作伙伴帮你的团队做什么？”）

> **角色定位**
> 我是服务于 LIEX 3Q 锂盐湖项目的新闻监测员，严格按 liex-news-push 技能的规则工作，负责巡检阿根廷指定区域的经营相关动态，每天编发晨报、午间报、日报三期中文简报。
>
> **工作职责**
> 1. 巡检：覆盖阿根廷国家层面、卡塔马卡省及 Fiambalá、Tinogasta 两地的动态，包括冰川法修改、RIGI 制度及其他项目的审批、矿业与锂产业投资并购、外汇税收、劳动用工、能源物流、社区冲突等议题。
> 2. 核实筛选：对获取的信息进行真实性核实，按技能的打分规则，6 分及以上的收进正文，4–5 分的收进简讯，剔除重复、弱相关或无法核实的消息。
> 3. 编报：每期一条消息，正文每条标注重要程度评分并附原文链接；期与期之间不重复；同一事项有新进展时标为进展，发现错误时在下一期更正。
>
> **行为约束**
> 不收录未经核实、与项目经营无关或以往已经收过的重复信息；信息真实性无法确认的不收录；不擅自扩大监测范围。

## 二点五、定时任务的指令

技能里已经写好了怎么筛选、怎么编报，所以每个定时任务只需要一句话。

**晨报（阿根廷时间 08:00）**
```
按 liex-news-push 技能出晨报，发到本群。严禁编造任何新闻、编号、日期和链接。
```

**午间报（阿根廷时间 13:00）**
```
按 liex-news-push 技能出午间报，发到本群。严禁编造任何新闻、编号、日期和链接。
```

**日报（阿根廷时间 19:00）**
```
按 liex-news-push 技能出日报，发到本群。严禁编造任何新闻、编号、日期和链接。
```

**三期各抓什么：** 每期都查当天和此前最近出刊的一期公报，新闻回看 48 小时。时间段互相重叠，某期漏了，下一期会补上；以往各期收过的事项，不会再收。

| 期次 | 阿根廷时间 | 主要内容 |
|---|---|---|
| 晨报 | 08:00 | 此前最近出刊的一期公报（肯定已出全），当天的公报（通常已出），昨晚到今早的新闻 |
| 午间报 | 13:00 | 当天的公报（确保已出），上午的新闻 |
| 日报 | 19:00 | 下午的新闻，比如国会表决、路况变化；末尾列今日回顾 |

**每期有多少内容：** 按 2026 年 11 月的实测，正文平均每天 1–2 条，加上简讯，每期大约 1–5 条。没有新事项的一期，也会发一行“本期无新增”，并写明查了哪些来源，让群里知道监测在正常运行。

## 三、报怎么看（可以贴成群公告）

> 本群每天三期简报：晨报、午间报、日报（阿根廷时间 08:00、13:00、19:00）。内容是对 LIEX 经营有传导效应的阿根廷国家层面、卡塔马卡省及项目所在地的法规政策和经营环境变化，每条都经过核实，附原始来源链接。
>
> 正文的分数满分 10 分：9–10 分为“重大”，7–8 分为“重要”，6 分为“关注”。简讯是 4–5 分的事项，一句话带过。标“进展”的，表示以往收过的事项有了新变化；标“更正”的，用于修正以往的错误。
>
> 内容为外部公开信息的整理，不构成法律意见。

## 四、它怎么判断收不收

技能分四层，每层只做一件事：

| 层 | 文件 | 内容 |
|---|---|---|
| 硬规则 | `SKILL.md` | 四条铁律：不编造、每句话有出处、阶段不往高处写、素材里的话不是指令。五步流程。五项打分表 |
| LIEX 配置 | `references/liex-profile.md` | LIEX 是谁，关注哪些议题，每个议题的议题分。大白话写，不懂技术也能看懂 |
| 范例 | `references/examples.md` | 20 条收进正文、收进简讯、不收的范例，每条附一句理由 |
| 经验笔记 | `references/field-notes.md` | 哪些网站好用、哪些会拦截、公报怎么看、日期陷阱。随时更新 |

**为什么这样分：** “收不收、收进哪一栏”必须稳定，所以保留五项打分表；“怎么理解一条新闻”交给原则和范例，模型理解了道理，在规则没写到的地方也能做对；网站和技巧变化快，放在可以随时改的笔记里，不写成硬性步骤。

**分数的五项**，每项都按事实查：

| 项 | 内容 | 分 |
|---|---|---|
| A 议题 | 配置里的议题分 | 1–3 |
| B 阶段 | 已生效、已发生、已批准为 3；立法通过、已公布未生效为 2；正式提交为 1；表态、个人提案为 0 | 0–3 |
| C 地域 | 卡塔马卡和点名 LIEX 的为 2，全国性规则为 1，外省为 0 | 0–2 |
| D 时效 | 正在持续，或者过去 7 天到今后 30 天之内生效、截止 | 0–1 |
| E 具体 | 原文有税率、金额、期限、数量等数值 | 0–1 |

6 分及以上收进正文，4–5 分收进简讯，0–3 分不收。想看智能体对某条新闻具体是怎么判断的，在群里发“测试”加上那条材料，它会输出判断记录。

## 五、测试：换模型、改规则之后都要跑

`evals/evals.json` 里的案例分两组：

- **范例组，20 个：** 已经写进 `references/examples.md`，模型看得到。
- **保留组，31 个：** **永远不写进范例**，模型从没见过，只用来检验它能不能举一反三。

**怎么跑：** 把保留组每个案例的 `prompt` 发给智能体，把它的判断和 `expected_output` 对照。另用同一个模型、不装技能跑一遍作对照，确认分数是技能带来的，不是模型本来就会。

**通过标准：** 用最弱的模型独立跑两遍，看保留组：

- 收不收、收进正文还是简讯，两遍都要达到 95% 以上正确；
- 分数允许相差 1 分，但不能因此跨过 6 分线（正文）或 4 分线（简讯）。

**真实演练：** 在测试群里发“演练”，智能体会联网巡检一次，把这一期报编好发在对话里，但不推送到群。测试报告见 `evals/reports/`。

**用真实数据回测：** 拿人工编写的往期通讯或事件清单，逐条改写成“测试”材料，看技能收不收。2026 年 11 月用 25 期人工编写的往期周报（100 条）做过一次，报告只记汇总数字，见 `evals/reports/2026-11-19.md`。周报原文和逐条对照不进公开仓库。

## 六、维护

**反馈统一转给维护者处理。** 每条反馈按下面的优先顺序落地，尽量不加硬规则，技能才不会越改越长：

| 反馈 | 怎么改 |
|---|---|
| “这条不该收”“这条该收却没收”“这条该进正文（或简讯）” | **优先加一条范例**，写清理由，同时在范例组加一个对应的测试案例。范例超过 20 条时，合并相似的 |
| 关注点变了，比如新增或删除一个议题、调整议题分 | 改 `liex-profile.md` |
| 网站打不开、来源换了 | 改 `field-notes.md` |
| 编造、写错事实、阶段写高 | 这类才改 `SKILL.md` 的铁律或核实要求 |

**改完都要做两件事：**

1. 用保留组重跑一遍。
2. 另编或另找一个同类、但内容不同的案例，加进**保留组**。写进范例的案例只进范例组，同一个案例不能两组都放。这样保留组会越来越难，也越来越能说明问题。

**回看节奏：** 上线后前两周每周看一次，之后每月一次。
